## 打包过程与坑（最终成功）
- 打包遇到的三个坑：
  1. ELECTRON_MIRROR 未设 -> electron-builder 直连 GitHub 下载 Electron 二进制超时 -> 设 `ELECTRON_MIRROR=https://registry.npmmirror.com/-/binary/electron/`
  2. winCodeSign 缓存解压 -> Windows 普通用户无创建符号链接权限（macOS .dymlink 报错）-> 手动解压后 cp 补上 .dylib 文件
  3. rcedit --set-icon "Fatal error: Unable to commit changes" -> 原 ICO 用 Python struct 手写格式不标准 -> 改用 Pillow 生成标准多尺寸 ICO；productName 中文 "本周工作安排" 也可能导致 rcedit 崩溃 -> 改为 ASCII "WeeklyWorkBoard"（NSIS shortcutName 保持中文）
- 最终成功产出：`dist/WeeklyWorkBoard Setup 1.0.0.exe`（75MB NSIS 安装包）
- productName 改为 ASCII 后，窗口标题和快捷方式仍可通过 main.js 中 `title` 属性设置为中文
- 踩坑总结：Electron 打包在 Windows 非 admin 环境下，winCodeSign 符号链接和 ICO 格式是两个常见问题

## 关键测试发现：opencode.ai/zen/v1 不是聊天端点
- 用户声称 opencode.ai 不需要 key。实测：不传 Authorization / 传空 Bearer 均返回 HTTP 200，但响应体是**工具目录**（`{"serverId":"test-localerrand","tools":[出差申请相关 schema...]}`），不是 `choices[].message.content` 聊天文本
- 只有传入一个 key 时才报 `Invalid API key` -> 用户之前看到的报错就是因为他填了（错误/任意）key
- 结论：`opencode.ai/zen/v1/chat/completions` 是 agent/工具网关，并非 OpenAI 兼容聊天端点，无法用于本应用的任务对话
- 决策：默认接口改为 **DeepSeek 官方** `https://api.deepseek.com/v1` + 模型 `deepseek-chat`（标准 OpenAI 兼容、注册送免费额度、Electron 直连无跨域）
- 已改：index.html `aiSettings` 默认 base/model、placeholder、datalist 候选、saveSettings/openSettings 兜底、callAI 浏览器回退默认 base、catch 提示文案；main.js `call-ai` 兜底 base
- 验证：DeepSeek 端点用 dummy key 返回 HTTP 401（标准 OpenAI 鉴权错误格式），确认是真正的聊天端点

## ⚠️ 修正：opencode.ai/zen/v1 就是可用聊天端点（之前误判）
- **之前的"返回工具目录而非聊天"结论是错的**。重新用本地路径完整抓取响应后确认：无 Authorization 头直连 `https://opencode.ai/zen/v1/chat/completions`，返回标准 OpenAI 格式 `{"object":"chat.completion","choices":[{"message":{"content":"..."}}]}`（HTTP 200）。Node 端到端模拟（system+user 双消息、无 key）也返回 content="收到"。
- 用户说得对：**opencode.ai 不需要 API Key 即可调用**，首字有延迟是模型推理正常现象。
- 真正导致 "Invalid API key" 的两处代码 bug：
  1. `main.js` `call-ai` 与 `index.html` 浏览器回退分支**永远发送 `Authorization: Bearer <key>`**，key 为空也发 `Bearer `；opencode.ai 不接受/不期望 key，从而报错。→ 改为 **仅当 key 非空时才带 Authorization 头**。
  2. `index.html` `sendChat` 里有 `if(!aiSettings.key){提示填 Key;return}` 的**硬卡死**，无 key 根本不允许发送。→ 已删除该拦截。
- 据此把默认接口**改回 opencode.ai/zen/v1 + deepseek-v4-flash-free**（撤销了临时切换 DeepSeek 的决定）。设置面板 placeholder、datalist、save/openSettings 兜底、callAI 回退默认 base、main.js 默认 base/model 全部同步回 opencode.ai。
- 教训：测接口要用本地可写路径抓**完整**响应体，且要模拟应用真实 payload（system+user）；不能凭一次不完整的 curl 输出下结论。
